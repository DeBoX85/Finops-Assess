# 0005 Optional export write mode (PROPOSED, needs owner sign-off on rule 1 wording)
Date 2026-10-18. Status: proposed.
Owner request: a toggleable, opt-in feature that lets the tool create and run a Cost Management export, then import the result. Fallbacks: customer exports from the portal and hands over the file; tool reads existing exports.
Facts (Microsoft Learn, read 2026-10-18): creating an export is a PUT needing Cost Management Contributor (subscription) or a contributor-level billing role; the destination storage account must exist; with a storage firewall, Owner on the account or a custom role with roleAssignments/write and permissions/read is needed at creation; Cost Management assigns Storage Blob Data Contributor to the export's managed identity itself; running an export is a POST (Exports_Execute). UNVERIFIED: temporary-role (PIM) behaviour, service principal creation of exports, whether the portal calls the same API.
Levels: 1 import a customer-provided FOCUS/cost file offline (default, no Azure permissions); 1.5 tool prints exact portal steps/ARM/CLI for the customer admin; 2 read-only cost APIs (Query, Cost Details), needs allowlist widening (own ADR); 3 opt-in write mode.
Design constraints for level 3: separate client class so the default client can never write; allowlist limited to exports on a customer-approved scope; explicit flag plus named profile plus confirmation of the exact calls (dry run); every write recorded in the manifest and shown in the report; cleanup step (delete export) and role revocation reminder; tests proving default mode still blocks all writes; default off.
Consequence: CLAUDE.md hard rule 1 would read "read-only by default; writes only in opt-in export mode". Not changed until the owner approves the wording.
